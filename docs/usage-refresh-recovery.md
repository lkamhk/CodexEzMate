# 用量更新與 Codex 路徑恢復（1.22.1）

- 用量顯示依照基本設定的更新間隔運作，不再因 Goal 監控已啟用而略過定時更新。
- 暫時的背景讀取錯誤不會令整個更新迴圈永久停止。手動及定時讀取會避免互相重疊，較舊的回應不會覆蓋較新的用量。
- 首次啟動的快取及讀取失敗時不再當作即時額度：百分比顯示 `—`，並停用使用 reset，直到重新取得資料。
- Codex 桌面版本目錄更新後，讀取連線會比較解析後的實際執行檔；路徑、執行檔或登入檔變動時重建連線。重建會等待已發送的請求結束，不會自動重送命名或 reset 操作。
- 已儲存的官方 Codex 版本路徑會重新解析到已安裝的新版。代管啟動／重試時亦會修正路徑；自訂位置的有效執行檔仍保留。
- 正在運行的代管程序不會因偵測到更新而被強制終止；用量讀取可改用新版獨立連線，代管下次啟動會使用新版。

## 網絡錯誤

`RPC -32603` 代表 App Server 回傳內部錯誤，不能單憑此碼判定是否登入失效。
若使用 Proxy，請確認該 Proxy 可連接 `https://chatgpt.com`；例如 HTTPS CONNECT 回傳 502 時，修正程式路徑亦不能恢復網絡。
程式會保留使用者的 Proxy 設定，不會自動繞過代理。修復 Proxy 或在設定選擇可用連線後，再按重新整理。
